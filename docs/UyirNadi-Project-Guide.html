1. What UyirNadi is

UyirNadi is a responsive healthcare-management website. It gives a person one place to track everyday health information, prepare for medical appointments, keep documents private, and get clearly labelled informational AI guidance. It also gives doctors and administrators their own workspaces.

The idea in simple terms: a patient sees their own health dashboard; a doctor sees only patients connected through approved appointments; an administrator manages people, appointments, education content, and emergency contacts.

What the product does not do

  • It does not diagnose illness, prescribe medication, or change a dosage.
  • It does not contact emergency services automatically.
  • It does not present AI output as a medical decision.
  • It does not give doctors access to private reports until the patient shares them and an approved appointment relationship exists.

Who uses it

Patient / user

Tracks wellbeing, stores documents, books appointments, reads health education, and uses the AI tools as informational support.

Doctor

Manages availability and appointments, sees relevant connected patients, and views only reports the patient has deliberately shared.

Administrator

Creates accounts, manages doctor profiles and appointments, publishes health tips, manages feedback and emergency contacts, and sees platform-level metrics.

Platform owner

Configures Firebase, storage, security rules, the optional Gemini key, and production deployment settings.

3. The user interface

The visual design uses light backgrounds, dark readable text, teal and green healthcare accents, generous spacing, subtle borders, and the supplied UyirNadi logo. The design adapts intentionally for each screen size.

How navigation works

Desktop and laptop

A fixed sidebar gives quick access to the dashboard, health tools, appointments, documents, education, profile, and feedback. The top area contains search and notifications.

Phone

A bottom navigation shows the main destinations. A collapsible menu keeps less-frequent features available without crowding a small screen.

Loading and empty views

Skeleton placeholders appear during loading. Empty sections explain what is missing and provide a direct action, such as “Upload report” or “Book appointment”.

Accessibility

Forms have labels and error messages, controls work with a keyboard, and colour is not the only way information is communicated.

5. How the website connects to the backend and database

The visible interface does not connect directly to privileged services. It asks the Next.js server to perform protected operations. This keeps keys and sensitive decisions away from the browser.

Person’s browser→Next.js pages and forms→Protected server API routes
↓
Firebase AuthenticationFirestore databaseCloud StorageGemini AI / OCR

A simple example: saving water intake

The user taps “Add water” and enters an amount.
The form validates the value and sends it to a protected server route.
The server checks the signed-in user and allowed request origin.
The record is saved only under that user’s private Firestore path. The chart updates from saved records.

A simple example: booking an appointment

The user selects a doctor, date, and available slot.
The server verifies the user, date, slot, and doctor information.
A Firestore transaction checks that the slot is still free at that exact moment.
The appointment is created with a status such as pending or confirmed. Notifications can be shown in the app.

A simple example: analysing a document

The user selects an allowed file type and sees a preview.
The server confirms the file signature, size, and private storage path.
The file is stored under that user’s Firebase Storage folder.
Only after consent, the server sends the document to the configured OCR/AI provider and saves the returned informational summary.

Why this approach is safer

  • The Gemini key and Firebase service-account key exist only on the server.
  • Browser pages use a short-lived Firebase sign-in token only to establish a protected server session.
  • Server routes verify the session and role for each sensitive action.
  • Database rules provide another layer of protection if a request reaches Firebase directly.

7. Security, privacy, and AI safety

Account protection

  • Firebase Authentication handles passwords and login. Passwords are never stored in Firestore.
  • Each account has a trusted server-assigned role: user, doctor, or admin. The browser cannot choose its own role.
  • After sign-in, the app exchanges the Firebase token for an httpOnly session cookie. Browser JavaScript cannot read this cookie.
  • Protected pages redirect unauthorised visitors to sign-in. Protected API routes repeat the role check on the server.

Data protection

  • Firestore and Storage rules are included in the project: firestore.rules and storage.rules.
  • Upload routes allow only PDF/JPG/JPEG/PNG, validate the actual file signature, limit uploads to 8 MB, and restrict files to private owner paths.
  • Cross-origin state-changing requests are rejected using the configured application URL.
  • Firebase App Check can be enabled after its reCAPTCHA configuration is complete, adding another layer against automated abuse.

AI safety rules built into the product

  • Every AI experience states that it offers informational guidance and does not replace a clinician.
  • The system prompt tells the AI not to claim it is a doctor, prescribe medicine, change a dosage, or invent missing findings.
  • Emergency symptoms are directed toward immediate professional or emergency care.
  • Report explanations are limited to text extracted from the uploaded document. If a reference range is missing, the app says so.
  • Users must consent before a private document is sent to the configured AI service.
Before a public healthcare launch: deploy the Firebase rules, enable App Check, rotate any service-account key that has been shared, configure a production HTTPS domain, and have qualified legal, privacy, and healthcare professionals review local obligations.

What needs to be configured for every feature to be live

  1. Cloud Storage: In Firebase Console, open Build → Storage and create the bucket. Then deploy the included Storage rules. This enables file upload and retrieval.
  2. Gemini: Create a Gemini key in Google AI Studio and add it to the server environment as GEMINI_API_KEY. Do not put it in browser code or share it in chat.
  3. Firebase rules: Use Firebase CLI to deploy firestore.rules and storage.rules to the correct project.
  4. Production hosting: Deploy to Firebase App Hosting, Vercel, or another Node-compatible platform. Add all environment variables there and set APP_URL to the real HTTPS domain.
  5. Doctor publication: Add verified qualifications, specialisation, availability, fee, and profile description before making a doctor visible to patients.
